현재 이 컴퓨터에 저장된 최신 외부 눈·두피 사진으로 자동 라벨링부터 기존 VLM 추가 학습, 저장, 재로드, 결과 기록까지 이어지는 실행 스크립트를 준비해라. 사용자가 직접 터미널에서 한 번 실행한 뒤 자리를 비워도 나머지 단계가 자동으로 이어지는 것이 목표다.

역할을 분명히 한다. Codex는 로컬 경로 탐색, 환경 설치, 모델 준비, 설정 생성, 실행·조회·추론 스크립트 작성과 점검을 맡는다. 전체 라벨링과 학습 시작은 사용자가 직접 한다. 이전의 'Codex가 백그라운드 실행까지 시작' 지시는 이 요청으로 대체된다. 준비 확인을 위해 전체 데이터 라벨링이나 시험 학습을 시작하지 않는다. 필요한 경우 소량의 분리된 샘플 추론으로 모델 로딩만 확인할 수 있다.

1. 실제 로컬 환경과 데이터를 직접 확인한다.
OS, CPU 아키텍처, GPU/VRAM, 드라이버, Python/Conda/venv, 남은 저장공간, 기존 학습 프로세스를 확인한다. 프로젝트 설정과 사용자의 Downloads·데이터 폴더·마운트된 데이터 디스크 범위에서 최신 사진과 기존 VLM 체크포인트를 찾는다. 폴더 경로를 사용자가 모른다고 해서 바로 질문하고 멈추지 않는다. 필요한 경로는 실제 파일, 수정 기록, 사진 수와 대표 샘플로 확인하고 선택 근거를 남긴다. 관련 없는 개인 파일을 읽거나 업로드하지 않는다. 원본 사진은 보존한다.

2. 입력 종류를 구분한다.
안구는 일반 카메라의 외부 눈 사진이며 안저 사진을 사용하지 않는다. 두피는 현미경 사진이다. 폴더명만으로 혼합 자료를 같은 입력으로 처리하지 말고 대표 이미지를 실제로 확인한다. 기존 JSON/CSV 등 정답 근거가 있으면 보존하되 폴더 이름을 임의의 확정 질환 라벨로 만들지 않는다.
안구가 단안 crop이면 그대로 사용한다. 얼굴 전체나 양쪽 눈 사진이면 mediflow-kiosk-core의 실제 MediaPipe 전처리와 의존성을 확인해 단안 ROI 준비 스크립트를 작성하고 전체 실행의 앞 단계에 연결한다. 원본과 crop의 연결 및 같은 원본/사람/세션 그룹을 유지한다. ROI 실패 사진을 얼굴 전체로 대신 분류하지 말고 제외 사유를 기록한다. 자동 modality 구분이 불가능한 자료는 섞지 않고 별도로 기록한다.

3. 실제 분류기와 환경을 연결한다.
kiosk_setup_models.py로 필요한 가중치를 내려받아 고정 commit/크기/SHA-256을 확인한다. 안구는 Augmented_EffNet_V1_B0_best.pth에 대응하는 mediflow_eye loader와 실제 클래스 순서를 사용한다. 두피 첫 실험은 양호가 포함된 public6를 사용한다. camera5는 정상 클래스가 없는 별도 카메라 적응 모델임을 기록하고 정상 사진까지 무조건 질환으로 분류하는 기본값으로 쓰지 않는다. 원본 모델 계약의 전처리를 유지한다.
분류기 CPU 환경과 VLM CUDA 환경을 분리한다. CPU용 torch 설치로 기존 학습용 환경을 바꾸지 않는다. 가상환경의 bin/python 심볼릭 링크를 실제 시스템 Python 경로로 풀지 않는다. 소량의 실제 사진으로 모델 로딩과 출력 형태를 확인하고 전체 이미지 수 기준 예상 소요 시간을 기록한다.

4. 기존 VLM 추가 학습을 준비한다.
완료·재로드 기록이 있는 호환 VLM 체크포인트와 원래 학습 config를 찾고 선택 근거를 남긴다. 실제 training_template, initialization_adapter, 원래 공용 data_root를 로컬 설정에 채운다. 기존 VLM을 이어서 학습하는 작업이므로 start_from_base=false를 유지한다. 분류기의 .pth/.keras를 VLM 체크포인트로 사용하지 않는다. 기존 GPU 잠금과 사용량 기록을 유지한다. GPU에 맞게 기존 엔진이 지원하는 batch/gradient accumulation/정밀도 옵션만 사용하며 기본 실행은 유한한 한 번의 데이터 통과로 한다.
기존 VLM 파일이나 학습 환경을 찾을 수 없다면 가능한 설정·스크립트 준비는 완료하고, 실행에 필요한 정확한 파일이나 환경을 남긴다. 이 경우 준비 상태는 BLOCKED로 기록한다. 다른 기본 VLM으로 몰래 대체하거나 학습 준비가 끝났다고 보고하지 않는다.

5. 사람 검수 없이 진행하는 실험을 명시한다.
pseudo_labels.allow_train=true를 사용하고 자동 실행에는 --allow-pseudo-validation을 명시한다. 자동 라벨은 teacher_pseudo로 유지하며 human_reviewed나 source_supported로 바꾸지 않는다. 기본 채택 기준 0.95 confidence/0.15 margin을 출발점으로 사용하고 보정된 정확도라고 해석하지 않는다. 조건을 통과한 train/validation 자료가 없으면 원인을 기록하며 성공시키기 위해 무조건 임계값을 없애거나 데이터 분할 검증을 우회하지 않는다.
같은 사람/세션/원본 crop은 같은 split에 유지한다. 사람 구분 정보가 없으면 그 한계를 기록한다. test 분할은 보존하고 검수된 정답이 없는 test의 질환 정확도를 계산하지 않는다. 검증 loss는 teacher 예측에 대한 실험 결과로 표시한다. 빈 검수 CSV 생성은 허용하지만 사용자 검수를 기다리는 대화 단계는 넣지 않는다.

6. 사용자가 직접 실행할 로컬 스크립트를 만든다.
데이터·모델·가상환경·저장소·설정의 실제 절대경로를 채워 넣은 다음 파일을 저장소 밖의 로컬 실행 폴더에 생성한다. 기존 파일은 보존하며 사용자가 경로를 다시 편집하거나 가상환경을 수동으로 활성화하지 않아도 되게 한다.
- run_all.sh: 새 run 이름으로 scripts/kiosk_autorun.py를 실행한다. 실제 --config, --label-python, --train-python, --name, --allow-pseudo-validation을 전달한다. 필요한 ROI 준비 후 scan → label → review 양식 생성 → export → prepare → train → reload → results --save --plot이 이어진다. 단계 실패나 부분 라벨링 실패를 무시하지 않는다.
- status.sh: 선택한 실행의 상태 파일과 로그를 읽어 라벨링 중인지 학습 중인지, 현재 진행 상황과 실패 사유를 표시한다. 준비 단계에는 학습 prepared.json이 아직 없을 수 있으므로 자동 실행의 state.json도 사용한다. 데이터 처리나 학습을 시작하지 않는다.
- results.sh: 선택한 실행의 설정 복사본으로 기존 results 명령을 호출해 모델·loss·결과 경로를 표시한다. 학습을 시작하지 않는다.
- predict.sh: source-id(eye 또는 scalp)와 사진 경로를 받아 저장·재로드된 VLM의 새 사진 추론을 실행한다. 모델이 준비되지 않았으면 명확한 이유를 표시한다.
- resume.sh: 선택한 기존 run의 지원되는 체크포인트에서 재개한다. 새로운 전체 학습으로 대체하지 않는다. 사용자가 이 파일을 실행할 때만 재개한다.
실행 이름과 설정 복사본을 공통으로 기록해서 조회·결과·추론 스크립트가 같은 run을 사용하도록 한다. run_all.sh의 기본 실행은 터미널 전경에서 상태와 로그 위치를 보여준다. 사용자가 명시적으로 선택하는 --background 옵션 또는 별도 백그라운드 실행 명령도 준비할 수 있다. nohup/stdin 분리/로그 저장 및 가능한 systemd-inhibit로 터미널 종료·일반 절전에 대비하되, Codex가 이를 대신 실행하지 않는다.
셸 문법, 경로, 명령 연결, 환경 import와 필요한 작은 샘플 추론을 점검한다. 검사 명목으로 run_all.sh, 전체 label, train, resume 또는 GPU 학습 worker를 실행하지 않는다.

7. 사용자에게 남길 내용
실제로 선택한 사진 폴더와 사진 수, 안구 crop 필요 여부, teacher 모델, 기존 VLM 체크포인트, 생성한 스크립트 경로와 점검 결과를 짧게 보고한다. 준비가 완료되면 READY_NOT_STARTED로 표시하고 사용자가 그대로 복사해 실행할 실제 경로가 채워진 시작·진행 조회·결과 조회·재개·새 사진 추론 명령을 준다. 실행 전이므로 실제로 없는 학습 PID나 학습 결과를 보고하지 않는다. 로컬 설정·사용자 사진·모델 가중치·라벨 파일을 공개 Git 저장소에 올리지 않는다.

이 작업의 완료 조건은 사용자가 직접 터미널에서 스크립트를 한 번 실행하면 자동 라벨링부터 기존 VLM 학습·저장·재로드·결과 기록까지 이어지고, 나중에 별도 스크립트로 결과 조회와 새 사진 추론을 실행할 수 있도록 실제 파일과 설정을 준비하는 것이다. 전체 실행 시작은 사용자에게 맡긴다.
